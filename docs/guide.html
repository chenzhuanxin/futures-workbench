使用说明

本文档介绍「期货数据工作台」的完整安装、配置、抓取、查看与导出流程。这是一个运行在你本机上的网页应用 —— 数据全部落地到你自己的硬盘，不上传任何服务器。

Windows 免安装 Python 3.9+ 离线可用界面 数据本地留存 v1.0.0

1三种运行方式

方式 A：直接运行 exe（推荐，无需装 Python）

从 Releases 下载 FuturesWorkbench-v1.0.0-win64.exe，放到任意目录（例如 D:\FuturesWorkbench\）双击运行即可。程序会自动打开浏览器并跳转到 http://127.0.0.1:8770。

⚠
首次启动需要等待解包

单文件 exe 内置了 Python 运行时与数据抓取依赖，首次启动会先解包到系统临时目录，约需 10～40 秒（视磁盘速度）。之后启动会快一些。请耐心等待浏览器自动打开。

方式 A+：直接载入随附数据包（免抓取）

首次全量抓取约需 1 个半小时。若只想先看看效果，可以直接用 Release 页面附带的 futures-daily-k-data.zip（约 84 MB，解压后约 313 MB）：

① 下载解压，得到 期货日K数据/ 目录，内含 91 个品种 xlsx（每个品种含「各月份合约」与「加权合约」两个 sheet）+ 汇总_全部品种.xlsx 汇总表；
② 把该目录放到 exe 同目录（放任意位置也可以）；
③ 网页左侧「本地数据」面板 → 该文件夹 → 载入本地数据，秒级恢复全部结果。

ℹ
数据为打包时快照，行情截至 2026-10-11

需要最新数据时，在左侧重新执行一次抓取即可；也可先载入数据包再选择性地补抓。

方式 B：源码运行

已安装 Python 3.9 及以上版本时：

# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动
python app.py

Windows 用户也可以直接双击项目里的 启动.bat，脚本会自动检测并安装缺失依赖，然后启动服务。

方式 C：换端口 / 不自动开浏览器

# 指定端口（默认 8770，被占用时自动顺延到 8771、8772…）
set PORT=9000 && python app.py

# 不自动打开浏览器（服务器 / 远程桌面场景）
set NO_BROWSER=1 && python app.py
ℹ
服务只监听 127.0.0.1

程序仅绑定本机回环地址，局域网内其他机器无法访问，也不对外暴露任何端口。关闭控制台窗口 = 停止服务。

2界面总览

界面分为四个区域，从左到右、从上到下依次是：

左侧 · 配置区 抓取参数

交易所、品种、日期区间、并发线程、输出与缓存目录，以及「本地数据」载入面板。

顶部 · 状态栏 数据源标识

显示当前数据来自「实盘抓取」、「本地数据」还是「文章示例」。

中部 · 内容区 四个页签

总览 / 品种汇总表 / 品种详情 / 运行日志。

底部 · 操作条 进度与导出

进度条、保存位置、格式与范围、「保存到本机」按钮，以及可折叠的数据源说明。

四个页签各做什么

页签内容
总览 6 张 KPI 卡片（品种数、总 K 线条数、上市最久、最新上市、历史最高价、涉及交易所）+ 交易所分布环形图 + 各交易所明细（品种数、占比、K 线条数）。
品种汇总表 全部品种的 14 个统计字段。支持点表头排序、关键词搜索；点击品种代码可直达该品种详情。
品种详情 按品种查看 K 线图：加权合约、全部合约、12 个月份分组视图；支持平移缩放、技术指标、极值定位。
运行日志 抓取过程的实时日志，包含每批次进度、缓存命中情况、异常与重试信息。

3抓取配置详解

交易所

可多选。每个交易所下方会显示其数据源起始日期，起始日期之前的请求会被自动跳过，避免大量无效请求。

交易所代码数据起始说明
中金所CFFEX2010-04-16股指期货、国债期货
上期所SHFE2004-06-01金属、能源化工等
郑商所CZCE2010-08-25更早日期官方接口不提供逐日数据
大商所DCE按合约枚举官网被 WAF 拦截，走新浪按合约兜底
上海国际能源交易中心INE2018-03-26原油、20 号胶、低硫燃油、国际铜、集运指数
广期所GFEX2022-12-22工业硅、碳酸锂、多晶硅等

品种

  • 按交易所分组展示，每组有「全选 / 反选」复选框。
  • 顶部搜索框可按代码或中文名过滤，例如输入 沪 会列出沪铜、沪铝、沪金、沪银、沪锌、沪铅、沪镍、沪锡。
  • 全部不勾选 = 抓取所选交易所的全部品种；只要勾选任意一个，就只抓这些品种。

日期区间

  • 起始日期留空 → 使用各交易所的数据源最早日期（见上表）。
  • 结束日期默认今天；非交易日会被接口自动跳过。

并发线程

1～32，默认 8。首次全量建议调到 16；网络状况一般时 8 更稳妥。设得过高可能触发交易所限流，反而变慢。

DCE 枚举起始年

大商所走新浪按合约枚举时，从这个年份开始枚举各交割月合约。默认 2000，一般不用改。

输出目录 / 缓存目录

  • 点「浏览…」会弹出 Windows 系统原生文件夹对话框，选完自动回填真实绝对路径。
  • 输出目录：最终 Excel 结果落地位置。
  • 缓存目录：抓取过程中的增量缓存（每个交易所一个 .pkl）。强烈建议保留 —— 有了缓存，二次运行只补新日期，几分钟就完成。

仅用缓存

勾选后跳过「缺失日期回补」环节。当缓存已经比较完整、你只是想快速拿到当前结果时使用，可以省掉大量检查请求。

✓
配置会被记住

输出目录、缓存目录、本地数据目录会写入程序目录下的 _prefs.json，下次启动自动回填，也会用于自动恢复上次结果。

4首次抓取与耗时

⏱
首次全量抓取约需 1 个半小时

六家交易所、全部品种、上市以来全部合约（含已退市）的历史日K，累计约 150 万行。请保持窗口开启，抓取过程中可以正常使用电脑做别的事。

耗时之所以长，是因为要按交易日逐日向各交易所官网请求「当日全部合约行情」，历史跨度长达 20 年以上。大商所部分还要按合约逐个枚举，请求量更大。

如何显著缩短时间

  1. 并发调到 16（左侧滑块）。
  2. 只选需要的交易所。例如只做上期所，时间可以降到十分之一以内。
  3. 只勾选部分品种。
  4. 保留缓存目录。第二次运行只补新数据，通常 1～3 分钟。
  5. 第二次以后根本不用抓 —— 用「载入本地数据」直接读上次的结果（见下一节）。

抓取过程中的操作

  • 底部进度条与百分比实时更新；「运行日志」页签可看详细过程。
  • 随时点「停止」中断任务。已完成交易所的缓存会保留，下次继续时可跳过。
  • 某个交易所接口临时不可达时，脚本会自动沿用该交易所已有缓存，不会中断整体任务。

5载入本地数据（免重复抓取）

这是避免「每次启动都要重新下载」的核心功能。左侧面板「本地数据」：选择目录 → 点「载入本地数据」，程序会扫描该目录并重建全部结果，不发起任何网络请求。

识别规则

程序会自动判断目录里有什么，按优先级处理：

目录内容处理方式速度
存在 _result.pkl 直接读取全量明细（程序自己生成的明细快照） 秒级（150 万行约 3 秒）
只有各品种 xxx_品种名.xlsx 逐个读取 日K线 工作表并合并重建，同时写回 _result.pkl，下次载入即秒级 视品种数量，通常十几秒～1 分钟

汇总数据从哪来

优先读取目录里的 汇总_全部品种.xlsx；如果没有，就根据明细现场重算，统计口径与抓取时完全一致。所以即使你只拷贝了几个品种的 Excel 过来，也能正确载入。

两种便捷用法

  • 可以直接指向上一级目录：例如选到项目根目录，程序会自动下钻到 期货日K数据、数据、output、out、data 等常见子目录名。
  • 重启零操作：上次载入 / 抓取的目录会记进 _prefs.json。下次启动时程序按「上次目录 → 默认输出目录」的顺序自动找回数据，日志里会打印 [启动] 已自动恢复数据：90 个品种。
ℹ
载入后顶部标识会变成「本地数据」

此时品种详情、按月分组、加权合约、K 线指标、导出功能全部照常可用，与实盘抓取的结果没有任何区别。

6保存到本机（导出）

底部操作条右侧：

  1. 点「选择位置…」弹出系统原生对话框，选一个目录。
  2. 选格式：Excel (.xlsx) 或 CSV (.csv，UTF-8 BOM) —— BOM 是为了 Excel 直接打开中文不乱码。
  3. 选范围：
    • 仅汇总表 → 只导出 14 个统计字段的汇总表。适合快速存档、做二次分析。
    • 全部行情文件 → 把整个输出目录（每个品种一个 Excel + 汇总表）完整拷贝过去。
  4. 点「保存到本机」。
✓
导出保留原始数据

图表展示层会过滤掉价格为 0 的占位数据，但导出文件保留原始内容，信息无损。如需连导出也剔除零值行，可以自行用 pandas 过滤 close > 0。

7品种详情与 K 线图

在「品种详情」页签选择品种（或从汇总表点品种代码跳转），即可查看该品种的完整 K 线。图表由项目自带的前端组件绘制，不依赖任何外部 CDN，断网也能用。

7.1 三种视图

顶部有一排视图按钮：

视图含义呈现方式
加权合约 把该品种全部合约合成为一条连续序列：每日按各合约持仓量加权计算开高低收（某合约持仓量为 0 时退化为成交量加权），成交量与持仓量求和。 蜡烛图 + 技术指标
全部合约 该品种上市至今的所有合约折线叠加。 多折线，图例可点选开关
1 月 … 12 月 按交割月份分组，跨年的同月份合约归为一组。例如「6 月」组会把 AU0806、AU0906 … AU2706 全部放在一起对比。 组内只有一个合约 → 蜡烛图；多个合约 → 折线叠加
ℹ
为什么同一个月份会有多个合约？

因为每年都有一个该月份的合约。像沪金（AU）这样的老品种，从 2008 年上市至今，每个月份组里都有约 19 个合约。把它们放在一起，就能直观对比同一个交割月份在不同年份的价格水平。

图表下方的「合约清单」列出该品种全部合约（含已退市）的代码、交割年月、首末交易日、K 线条数。点击任一合约即可切换为单合约 K 线（蜡烛图 + 指标）。

7.3 极值标注

  • 图上用虚线 + 标签标出历史最高价与历史最低价，标签含价格与日期。

  • 极值只统计正价格，不会出现「历史最低价 = 0」这种假象。

7.4 技术指标

指标参数说明

9零值数据处理规则

交易所日K接口在无成交的交易日会返回占位行，价格字段为 0。如果直接画进图里，会导致纵轴被拉到 0、所有曲线挤在顶部、历史最低价显示为 0、均线被稀释。程序统一按「期货价格不可能为 0」处理：

情形图表上的表现导出文件
开高低收全部为 0（无成交占位行） 整条不返回，不占日期轴、不绘制、不连线 保留原始行
开高低为 0、仅收盘有值 日期轴保留（能看出当日无成交），不画蜡烛；折线模式用有效收盘价绘制 保留原始行
折线模式下某合约某日收盘为 0 该点断开，也不参与纵轴范围计算 保留原始行
整个合约全部是 0 不再出现在合约清单里 —

把光标移到无有效行情的日期上时，提示条会显示「该日无有效行情（零值数据，未绘制）」。

10本地接口（API）

后端是一个本地 Flask 服务，所有接口都只在 127.0.0.1 可用。如果你想写脚本对接，可以直接调用：

方法路径说明
GET/health健康检查，返回版本号与是否以 exe 运行
GET/api/config交易所、品种清单、默认目录、上次使用的目录等
POST/api/run启动抓取任务（JSON：markets / start / end / out_dir / cache_dir / workers / keep）
GET/api/progress任务进度、百分比、日志、是否运行中
POST/api/stop中断当前任务
GET/api/summary当前汇总结果（含数据来源标识）
POST/api/demo载入内置示例数据（断网时预览界面用）
POST/api/load-local载入指定本地目录的数据
POST/api/local-scan预览某目录里有什么数据（不载入）
GET/api/variety?code=CU某品种的合约清单、月份分组、加权合约序列与极值
GET/api/contracts?code=CU&month=9某品种某月份分组下全部（跨年同月）合约的日K序列
GET/api/contract?symbol=CU2409单个合约的日K序列与极值
POST/api/export导出到指定目录（JSON：dir / format / scope）
POST/api/pick弹出系统原生文件夹 / 另存为对话框

示例：

# 载入本地数据目录
curl -X POST http://127.0.0.1:8770/api/load-local \
     -H "Content-Type: application/json" \
     -d '{"dir":"D:/期货数据"}'

# 取沪铜的合约分组与加权合约
curl "http://127.0.0.1:8770/api/variety?code=CU"

11常见问题 FAQ

Q1：双击 exe 后很久没反应？

单文件 exe 首次启动要解包内置的 Python 运行时与依赖（含 pandas、akshare），约 10～40 秒。杀毒软件实时防护也会拖慢首次解包。建议把 exe 放到固定目录（如 D:\FuturesWorkbench\），并加入杀毒软件白名单。

Q2：浏览器没有自动打开？

手动访问 http://127.0.0.1:8770。如果控制台里显示的端口不是 8770（例如提示「8770 端口被占用，已自动改用 8771」），就用控制台里显示的那个地址。

Q3：抓取到一半报错 / 卡住？

  • 交易所官网在收盘结算时段可能短暂不可用 —— 用缓存目录重跑即可，已抓到的不会丢。
  • 把并发线程调低到 4～8 再试。
  • 大商所官网反爬策略变化时，可能需要对源码做适配，欢迎提 Issue。

Q4：每次启动都要重新抓吗？

不用。只要输出目录和缓存目录不变，程序启动时会自动恢复上次结果；也可以手动用「载入本地数据」指向任意一份已有数据。

Q5：能导出成数据库 / Parquet 吗？

程序提供 Excel 与 CSV 两种导出。你要其它格式，可以直接读输出目录里的 _result.pkl：

import pandas as pd
df = pd.read_pickle("期货日K数据/_result.pkl")
df.to_parquet("futures.parquet")

Q6：数据是实时的吗？

不是。日K数据在当日收盘结算之后才会由交易所公布。盘中的当日数据通常不完整。本工具定位是历史研究 / 回测取数，不适用盘中交易决策。

Q7：为什么某个品种的历史最高价看起来不对？

注意极值是该品种全部合约的极值，不是主力连续合约的极值。远月合约在流动性差的时候可能出现异常报价，会拉高极值。你可以进「品种详情」定位到具体是哪个合约。另外，合约价格未做复权 / 不复权处理（期货合约本身不存在复权概念）。

Q8：可以放服务器上跑吗？

可以，但不建议直接暴露公网：没有认证机制。如需多人使用，请放在内网并加反向代理 + 身份验证。设置环境变量 NO_BROWSER=1 可关闭自动开浏览器。
