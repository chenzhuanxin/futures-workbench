为什么起始日期各不相同

表中起始日期是「该交易所数据源实际可用的最早日期」，不是交易所成立日期。例如中金所成立于 2006 年，但官网可检索的日行情数据从 2010-04-16 的沪深300股指期货（IF）上市首日开始。设置起始日期是为了避免对无数据的历史日期发起大量无效请求，把抓取时间花在真正有数据的日子上。

为什么郑商所从 2010-08-25 才有逐日数据

郑商所对更早的历史数据只提供「整年数据压缩包」形式，不提供按交易日的逐日查询。本工具走的是逐日接口，因此以 2010-08-25 为界。如果你需要 2010 年之前的郑商所数据，需要用整年包另行处理。

6统计指标口径

汇总表里的 14 个字段，定义如下（均基于该品种的全部合约，即合并的主力与远月、在挂与已退市合约）：

指标计算方式
上市日期 该品种所有 K 线中最早的交易日。对应的是首个合约（通常是该品种的第一个交割月合约）的上市日。
总交易天数 该品种出现过的交易日去重计数。同一天有多个合约在交易，只算 1 天。
总K线条数 该品种全部合约的 K 线总条数（不去重）。因此总是远大于「总交易天数」。
历史最高价 / 最高价日期 / 最高价合约 遍历全部合约的 最高价，取最大值；同时记录其发生日期与所属合约代码。只统计正价格。
历史最低价 / 最低价日期 / 最低价合约 遍历全部合约的 最低价，取最小值；同时记录日期与合约。同样只统计正价格。
主连平均收盘价 对每个交易日，取当日持仓量最大的合约作为「当日主力」；把每天的主力收盘价拼成一条连续序列；对该序列求算术平均。
主连平均结算价 同上，但取每日主力的结算价求平均。
⚠
关于「历史最高价」的一个常见误解

因为口径是全部合约，所以它会包含远月合约。远月合约在流动性差时可能出现异常报价，从而拉高极值。若要看「主力连续合约」的极值，请进「品种详情」看加权合约视图。

「主连」与市面「主力连续合约」的区别

本工具的「主连」是每日按持仓量动态选取主力合约后直接拼接，不做价格平滑 / 不做价差调整 / 不做复权。因此它在换月处会存在价格跳空，不能直接用于计算收益率或做回测。市面上的「主力连续合约」通常带有前后复权处理，两者数值会有差异。本指标的作用是快速了解该品种历史价格量级，不适合作为交易信号。

7加权合约合成算法

「品种详情」里的加权合约是本工具自建的连续序列，用于观察品种整体的价格水位与走势。算法如下：

对某个品种的每个交易日 T：
  1. 取出 T 日该品种全部有效合约（价格为正）
  2. 计算每个合约的权重 w_i：
       若该合约在 T 日的持仓量 > 0  →  w_i = 持仓量_i
       若全部合约持仓量都为 0        →  w_i = 成交量_i（退化）
  3. 加权合成当日行情：
       加权开盘 = Σ(开盘_i × w_i) / Σw_i
       加权最高 = Σ(最高_i × w_i) / Σw_i
       加权最低 = Σ(最低_i × w_i) / Σw_i
       加权收盘 = Σ(收盘_i × w_i) / Σw_i
  4. 量仓直接求和（不做加权平均）：
       加权成交量 = Σ成交量_i
       加权持仓量 = Σ持仓量_i
       同时记录当日参与合成的合约个数 n

与「主连」的口径对照

加权合约主连（主力连续）
构建方式全部合约加权平均每日只取一个持仓量最大的合约
换月跳空无（每天都重新加权，平滑过渡）有（换月日价格直接跳变）
反映内容品种整体价格水位最活跃合约的实际可交易价格
适用场景长期走势观察、量级判断需要贴近真实成交价的场景
ℹ
加权合约是分析工具，不是可交易合约

它没有对应的真实合约，不能下单、不能交割，其价格只是各合约的加权均值。用它可以观察趋势与量级，但不代表任何一张真实合约的报价。

8数据清洗与过滤规则

规则处理内容原因
只取期货，不含期权 只保留期货合约 期权合约在代码规则、定价方式上与期货完全不同，混在一起没有意义
过滤合成 / 指数合约 剔除合约代码以 0、88、888、99 结尾的序列（如 CU0、IF888） 这些是行情软件自带的「连续 / 指数」合成序列，不是真实可交易合约，会让「全合约」统计重复计数
剔除特殊非交易品种 剔除 OP、SC_TAS 交易所日行情中自带的非真实可交易序列
剔除无成交伪影行 导出时剔除 成交量 = 0 的行 未成交日交易所仍会返回占位行（价格字段常为 0 或结转收盘）。日志中会打印剔除条数
价格零值过滤（展示层） 价格为 0 / NaN 的 K 线不参与绘图、不参与指标计算、不参与极值统计 期货价格不可能为 0；零值会把纵轴拉到 0、稀释均线、让「历史最低价」变成 0。导出文件保留原始数据
字段类型标准化 所有数值列 pd.to_numeric(errors="coerce")；日期统一 YYYYMMDD / YYYY-MM-DD 不同交易所返回的字段名与类型不完全一致
非交易日 只对工作日发起请求；节假日由接口返回空自动跳过 减少无效请求

9网络稳定性处理

抓取 20 年历史、上百万条记录，网络层面的坑比数据层面更多。程序内置了以下容错：

DNS 强制 IPv4

部分交易所域名会被解析到本网络不可达的 IPv6 地址，导致 TCP 连接长时间停在 SYN_SENT 卡死。程序在启动时给 socket.getaddrinfo 打了补丁，只保留 IPv4 结果。

超时 全局默认超时

给 requests.get / post 打补丁，默认 20 秒超时，避免某个请求无限期挂住整个任务。

并发 线程池并行

按交易日 / 按合约并行抓取，线程数 1～32 可调。首次全量建议 16。

容错 沿用已有缓存

某个交易所接口临时不可达时，自动沿用该交易所已有缓存，不中断整体任务，日志中会标注。

可中断 随时停止

点「停止」立即中断，已完成的缓存全部保留，下次继续时自动跳过。

日志 全流程留痕

每次请求批次、缓存命中、异常与重试都写入运行日志，便于定位问题。

10增量缓存机制

缓存目录里每个交易所一个 .pkl 文件，存的是该交易所已抓取的全部明细。

期货数据缓存/
├─ CFFEX.pkl   SHFE.pkl   CZCE.pkl
└─ DCE.pkl     INE.pkl    GFEX.pkl

运行逻辑

  1. 开始抓取时，先读入各交易所的缓存。
  2. 比对请求区间与缓存已有日期，只请求缺失的日期。
  3. 抓完合并回缓存并写盘。

因此：第一次慢，之后快。第二次运行通常只需 1～3 分钟；若打开「仅用缓存」则跳过回补检查，更快。

⚠
不要随意删除缓存目录

删掉意味着下次要重新全量抓取（约 1 个半小时）。缓存文件是压缩存储的 Python pickle，体积可能达到数百 MB，属于正常现象。

输出目录里的另一个快照

除了缓存，输出目录里还有一个 _result.pkl —— 这是全量明细快照，专供「载入本地数据」功能秒级读取。它和缓存目录的 pkl 用途不同：缓存用于增量抓取，快照用于快速载入展示。

11已知限制与数据边界

时效性

  • 日K数据在当日收盘结算完成后才由交易所公布，通常为交易日 15:30 之后，夜盘品种可能更晚。
  • 盘中抓取得到的是不完整的当日数据。本工具定位为历史研究与回测取数，不适用盘中交易决策。

历史边界

  • 各交易所起始日期见第 2 节表格。早于该日期的数据无法通过本工具获取。
  • 郑商所 2010-08-25 之前、以及其他交易所官网未提供逐日数据的历史区间，均不在覆盖范围内。

字段缺失

  • 成交额、前结算等字段在部分交易所 / 部分历史日期不提供，会表现为空值。
  • 大商所与上期能源走新浪兜底，字段口径与官方公布值可能有细微差异。

口径差异

  • 主连为动态选主力后直接拼接，不做复权，换月处存在跳空，不可直接用于计算收益率。
  • 加权合约为自建指标，不是可交易合约。
  • 极值基于全部合约统计，包含流动性较差的远月合约。
  • 与 Wind、同花顺、文华财经等商业终端的主力连续合约（带复权）在数值上会有差异，属正常现象。

合规边界

  • 只抓期货，不含期权。
  • 抓取频率应自行控制，避免对数据源服务器造成压力。

12数据校验方法

拿到数据后建议做以下抽查，确认数据可信：

检查项方法期望结果
上市日期是否合理 在汇总表看「上市日期」 与该品种首个合约的真实上市日一致。例如沪铝/沪铜约为 2004-06-01，沪金约为 2008-01-09
价格量级是否合理 看历史最高/最低价 应在该品种的真实价格区间内，且均为正数（不应出现 0）
K 线连续性 在「品种详情」拖动、缩放查看 交易日之间间距均匀，无异常缺口（节假日正常跳过）
合约覆盖完整性 看合约清单中的合约数量 老品种应有上百个合约（含已退市）；新品种则应与其上市年限匹配
与官方交叉验证 挑一个具体交易日、具体合约，去交易所官网查当日行情 开高低收、成交量、持仓量应完全一致
零值残留 在「品种详情」看极值标注 历史最低价应为正数

用 pandas 自查

import pandas as pd

# 4. 单品种抽查：合约数与上市日
